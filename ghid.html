Vezi site-ul
Ghid de publicare

Ce încarci, unde, și ce faci în Vercel.

Ai deja cont pe GitHub și pe Vercel. Deci nu vorbim despre conturi. Vorbim exact despre fișiere, folder și butoane.

Răspunsul scurt
Ce fișier încarc index.html — plus celelalte 6, toate în același loc
În ce repository Unul nou, numit relieff-site
În ce folder În rădăcină. Nu într-un subfolder.
Ce link pun în Vercel Niciunul. Alegi repository-ul din listă.

Asta e miezul: Vercel nu primește un link. Îl autorizezi o dată pe contul tău GitHub și îți arată repository-urile ca o listă din care apeși Import.

1. Ce fișiere ai

Pachetul conține 7 fișiere. Toate stau unul lângă altul, în același folder. Nu există subfoldere obligatorii, cu o singură excepție: images/.

relieff-site/
├── index.html ← pagina Acasă (intrarea în site)
├── despre.html ← pagina Despre
├── servicii.html ← pagina Servicii
├── proces.html ← pagina Proces
├── contact.html ← pagina Contact
├── ghid.html ← acest ghid
├── styles.css ← toate stilurile, un singur fișier
├── script.js ← meniu mobil + animații
├── vercel.json ← spune lui Vercel că e site static
├── .gitignore ← ține afară fișierele de sistem
├── README.md ← notă pentru tine, nu se vede pe site
└── images/
    └── moodboard.png ← imaginea de fundal

De ce sunt doar fișiere simple: site-ul e static. Nu are bază de date, nu are server, nu are build. Browserul deschide index.html și atât. Asta înseamnă zero instalări, zero comenzi în terminal, zero configurări complicate — și un site care se încarcă foarte repede.

În folderul dezarhivat vezi 7 fișiere text/HTML plus un folder images cu o singură imagine. Dacă vezi un folder în plus numit relieff-site care conține totul, e la fel de bine — dar atunci când urci, urci conținutul lui, nu folderul.

2. În ce repository

Un repository nou, doar pentru site. Nu îl amesteci cu alte proiecte — altfel Vercel va încerca să publice și altceva.

  1. Intră pe github.com și autentifică-te.
  2. Sus în dreapta, apasă butonul + și alege New repository.
  3. La Repository name scrie exact: relieff-site
  4. Lasă Public bifat. (Private funcționează și el cu Vercel, dar Public e mai simplu la început.)
  5. Bifează Add a README file. Contează: fără el, repository-ul e gol și GitHub nu îți arată butonul de upload.
  6. Apasă Create repository.
Se deschide pagina repository-ului. Sus vezi numele relieff-site și eticheta Public. În mijloc vezi un singur fișier: README.md. În dreapta sus există un buton verde Code.

3. În ce folder — și cum urci

În rădăcină. Când deschizi repository-ul, ești deja în rădăcină. Nu intra în niciun folder, nu crea unul. Fișierele stau la același nivel cu README.md.

Urcarea, pas cu pas

  1. În pagina repository-ului, apasă Add file (buton lângă Code).
  2. Alege Upload files.
  3. Trage în fereastră toate fișierele: index.html, despre.html, servicii.html, proces.html, contact.html, ghid.html, styles.css, script.js, vercel.json, README.md.
  4. Trage și folderul images — GitHub îl păstrează ca folder.
  5. Jos, în câmpul de commit, scrie: Site Relieff — versiunea inițială
  6. Apasă Commit changes.
Te întoarce la pagina repository-ului și vezi toate fișierele listate, plus folderul images. Dacă un fișier lipsește, îl poți urca separat cu același buton Add file → Upload files.

Fișierul .gitignore — cazul special

Fișierele care încep cu punct sunt ascunse de sistemul de operare. Pe Windows, în Explorer: View → bifează Hidden items. Pe Mac, în Finder: Cmd + Shift + . (punct).

Dacă tot nu îl vezi, creează-l direct pe GitHub — metoda care merge întotdeauna:

  1. Add file → Create new file
  2. La nume scrie exact: .gitignore (cu punct în față)
  3. În conținut scrie: .DS_Store apoi enter, apoi Thumbs.db
  4. Commit changes

Sincer: .gitignore nu e obligatoriu pentru ca site-ul să funcționeze. Dacă te blochează, sari peste el — nu afectează publicarea.

Cum verifici că au ajuns toate

Pe pagina repository-ului trebuie să vezi 11 intrări: 6 fișiere HTML, styles.css, script.js, vercel.json, README.md, .gitignore — plus folderul images. Click pe images și verifică să fie moodboard.png înăuntru.

4. Ce faci în Vercel

Nimic din ce ai putea numi „link”. Patru click-uri și un buton de deploy.

  1. Intră pe vercel.com și autentifică-te.
  2. Apasă Add New… (dreapta sus) → Project.
  3. În secțiunea Import Git Repository ar trebui să vezi deja relieff-site în listă. Apasă Import lângă el.
  4. Dacă lista e goală: apasă Adjust GitHub App Permissions → în fereastra GitHub care se deschide, dă acces la repository-ul relieff-site → Install → revino în Vercel și reîncarcă pagina.
  5. La Framework Preset alege Other. (Nu Next.js, nu Vite — e site static.)
  6. Root Directory lasă gol. Build Command lasă gol. Output Directory lasă gol.
  7. Apasă Deploy.
Vezi un ecran cu un build care rulează câteva secunde — un cerc care se învârte și log-uri care defilează. Apoi apare o bifă verde și un ecran de felicitare cu confetti, textul Congratulations! și un buton Visit. Apasă-l: se deschide site-ul tău, live.

Dacă build-ul durează mai mult de un minut la un site static, ceva nu e în regulă — vezi secțiunea 7.

5. Cum arată linkul final

Vercel îți dă automat o adresă construită din numele proiectului:

https://relieff-site.vercel.app

Asta e adresa pe care o trimiți mai departe. Funcționează imediat, fără configurare.

Dacă vrei alt nume

  1. În proiectul din Vercel, mergi la Settings → General.
  2. La Project Name scrie numele dorit, de exemplu relieff.
  3. Apasă Save.

Noul link devine https://relieff.vercel.app. Vechiul link continuă să funcționeze o perioadă, apoi se retrage — folosește-l pe cel nou de acum înainte.

În Settings → General vezi câmpul Project Name cu numele actual. După salvare, în tabul Domains apare noul domeniu ….vercel.app marcat ca Valid Configuration.

Un domeniu propriu (de tip relieff.ro) se adaugă tot din Settings → Domains, dar cere cumpărarea domeniului și câteva înregistrări DNS. Nu e necesar ca să pornești.

6. Cum faci o modificare mai târziu

Nu editezi nimic în Vercel. Editezi în GitHub, iar Vercel preia automat.

  1. Deschide repository-ul pe GitHub și intră în fișierul pe care vrei să îl schimbi (de exemplu index.html).
  2. Apasă creionul din dreapta sus — Edit this file.
  3. Modifică textul direct în browser.
  4. Apasă Commit changes… → în fereastra care apare, apasă din nou Commit changes.
  5. Așteaptă ~30 de secunde, apoi dă refresh pe site.
În Vercel, la tabul Deployments, apare imediat o intrare nouă cu status Building, apoi Ready. Pe site, modificarea e vizibilă după refresh. Dacă nu se vede, forțează reîncărcarea cu Ctrl + Shift + R (Windows) sau Cmd + Shift + R (Mac).

De ce se întâmplă automat

Când ai importat repository-ul, Vercel a instalat o aplicație GitHub care ascultă după modificări pe acel repository. Fiecare commit — adică fiecare salvare de modificare — declanșează o republicare. Nu trebuie să apeși nimic în Vercel. Nu există „buton de upload” și nici „buton de sync”.

Dacă vrei să revii la o versiune anterioară: în Vercel, tabul Deployments, găsește publicarea bună, apasă cele trei puncte → Promote to Production.

7. Dacă ceva nu merge

Repository-ul nu apare în lista din Vercel

Cauză: aplicația Vercel nu are permisiune pe acel repository — se întâmplă des când ai mai multe conturi sau organizații pe GitHub.

Soluție: în pasul de import, apasă Adjust GitHub App Permissions. În fereastra GitHub, la Repository access alege Only select repositories și bifează relieff-site. Apasă Install (sau Save), apoi reîncarcă pagina din Vercel.

Pagina apare fără stiluri — doar text negru pe fundal alb

Cauză: styles.css nu a ajuns în repository, sau a ajuns într-un subfolder.

Soluție: verifică pe GitHub că styles.css e la același nivel cu index.html. Dacă e într-un folder, mută-l: deschide fișierul → creion → schimbă numele în styles.css fără cale → commit. Apoi redeploy.

Eroare 404 pe toate paginile

Cauză: fișierele au ajuns într-un subfolder, iar Vercel caută index.html în rădăcină.

Soluție: în Vercel, Settings → General → Root Directory. Dacă acolo scrie un nume de folder, șterge-l și lasă gol. Salvează și redeploy din Deployments → Redeploy.

Build failed

Cauză: aproape întotdeauna un Framework Preset greșit — Vercel încearcă să ruleze un build de Next.js pe un site static.

Soluție: Settings → General → Framework Preset → alege Other. Golește Build Command și Output Directory. Apoi Deployments → Redeploy.

Modificarea nu se vede pe site

Cauză: cache de browser, sau commit-ul nu s-a salvat.

Soluție: verifică în Vercel la Deployments că ultima intrare e Ready și are ora modificării tale. Dacă da, forțează reîncărcarea: Ctrl + Shift + R / Cmd + Shift + R. Dacă nu, refă commit-ul.

Imaginile nu se încarcă

Cauză: folderul images lipsește sau are alt nume (de exemplu Images cu majusculă — GitHub și Vercel fac diferență între litere mari și mici).

Soluție: verifică numele exact: images, cu literă mică, iar înăuntru moodboard.png. Calea din HTML e images/moodboard.png.
